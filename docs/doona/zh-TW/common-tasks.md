# 常見操作 {#common-tasks}

在標準版中調整路由、管理訂閱或排查流量。首次設定請從[路由第一條連線](tutorial.md)開始；精簡版請參閱 [doona lite](lite.md)。

修改規則前，先檢查[規則編輯條件](feature-requirements.md#req-rules)。儲存後的生效方式見[組態寫入](what-doona-can-change.md#change-sources)。


## 讓一個網站透過代理存取 {#one-site}

1. 開啟**連線** → **清單**，找到該網站的連線。
2. 按該列的新增規則圖示。
3. 將**依據**設為**完整網域**，將**出站**設為代理群組。
4. 檢查預覽和**插入位置**，把新規則放在可能先比對到同一流量的規則之前。
5. 按**套用**並檢查成功提示。如需集中處理多條修改，先按**暫存**，再依[暫存規則](routing.md#held-rules)的步驟套用。

如需包含子網域，或讓此路由在全域和直連模式下也生效，請依[網域規則步驟](#domain-family)操作。


## 讓網域及其子網域透過指定群組 {#domain-family}

1. 開啟**規則** → **路由規則**。若顯示檢視切換選項，先選擇**進階**，再按**新增規則**。
2. 將**依據**設為**網域後綴**，在**值**中輸入網域。
3. 將**出站**設為目標群組。
4. 若全域或直連模式也須遵循此規則，開啟**鎖定此出站**。
5. 將**插入位置**設在可能先比對到同一流量的規則之前。
6. 按對話框中的**新增規則**，檢查成功提示和清單中的新規則。

其他條件與規則順序的說明見[規則編輯器](routing.md#add-rule)。


## 讓一台裝置略過代理 {#device-bypass}

為裝置設定固定 IP 位址，以免位址變化後規則不再符合。

1. 在**規則** → **路由規則**中，若顯示**進階**，先選擇它，再按**新增規則**。
2. 將**依據**設為**來源 IP**，在**值**中輸入裝置的 IP 位址。
3. 將**出站**設為 `direct`，開啟**鎖定此出站**。
4. 將**插入位置**設在可能先比對到此裝置的規則之前。
5. 按**新增規則**，檢查新規則中的來源位址與出站是否正確。

在[追蹤模擬](routing.md#trace)中填入該來源位址，檢查最終命中哪條規則。


## 選擇群組內節點並恢復自動選擇 {#group-node}

先檢查[選擇節點與手動固定的條件](feature-requirements.md#req-group-selection)。

1. 開啟**策略**，展開目標群組的卡片。
2. 在節點網格中選擇節點。
3. 閱讀提示，確認選擇結果以及自動策略是否暫停。
4. 如需取消手動固定，開啟卡片的**更多操作**選單，按**恢復自動選擇**，並檢查提示中顯示的成員。

群組策略的說明見[策略群組](routing.md#policies)。


## 新增或重新整理訂閱 {#subscription}

先檢查[新增訂閱的條件](feature-requirements.md#req-nodes)和單獨的[重新整理條件](feature-requirements.md#req-subscription-refresh)。

1. 開啟**節點**，按**新增訂閱**。
2. 填寫**名稱**和**訂閱網址**，按**新增**。
3. 選擇新訂閱卡片，檢查節點。後端支援重新整理時，doona 會在新增訂閱後請求重新整理，並提示結果。
4. 以後需要重新整理時，按該卡片的更新按鈕。若宣告已儲存但重新整理失敗，先解決提示中的錯誤，再按更新按鈕。

訂閱包含節點後，可繼續[建立群組](tutorial.md)。


## 切換至全域模式 {#global-mode}

先檢查[出站模式的修改條件](feature-requirements.md#req-config-edit)。

1. 開啟**活動**。
2. 在**出站模式**中選擇**全域**，再在**全域出站**中選擇目標。
3. 按**套用**，閱讀確認對話框。
4. 在對話框中按**套用**，檢查提示和頁面顯示的模式。

如需恢復依規則路由，選擇**規則**，再按**套用**。

選擇全域出站也會選中全域模式。全域模式未選目標時，**套用**會停用；僅改變選擇不會生效。按**唯讀**可查看寫入限制；**此後端不提供**表示後端沒有提供此控制項可編輯的組態。


## 查明連線為何使用某個出站 {#why-outbound}

1. 開啟**連線** → **清單**，選擇目標連線。
2. 在詳細資料中查看**出站**、**鏈**和**規則**。
3. 在**更多操作**中按可用的**檢視命中的規則**。
4. 如需測試目前組態，按**追蹤此連線**，再按**開始追蹤**。

追蹤用於評估路由，不會重播連線。可用條件與結果解讀見[追蹤條件](feature-requirements.md#req-routing-trace)及[連線詳細資料](observe.md#connections)。


## 查看網域如何解析 {#dns-resolution}

先檢查 [DNS 查詢條件](feature-requirements.md#req-dns-query)。

1. 開啟**DNS** → **查詢**。
2. 填寫**網域**，選擇**類型**。
3. 若提供**上游**，保留**自動**可遵循組態中的 DNS 路由，也可選擇指定上游。
4. **略過快取**預設關閉。若診斷查詢需要略過快取回應，開啟此選項。
5. 按**查詢**，查看結果中的回應、狀態、上游和路由資訊。

如需查看已記錄的流量，開啟**解析記錄**。資料範圍見 [DNS 資料說明](observe.md#dns)。


## 更新地理資料 {#update-geodata}

先檢查[手動更新條件](feature-requirements.md#req-geodata-update)。

1. 開啟**設定**，找到**地理資料**。
2. 按**立即更新**。
3. 等待操作完成，檢查結果提示與資料檔案詳細資料。
4. 若更新失敗，依回報的階段查閱[地理資料更新錯誤](troubleshooting.md#geodata-update)。

修改來源或更新排程是另一項操作，見[地理資料設定](config-and-settings.md#geodata)及[這些修改的儲存位置](what-doona-can-change.md#change-geodata)。


## 在 doona 外修改檔案後重載 {#reload-honk}

先確認修改的設定需要[重載還是重新啟動](what-doona-can-change.md)，並檢查[後端是否支援重載](feature-requirements.md#req-reload-suspend)。

1. 按頂端列的**重載 honk**。窄螢幕下可在**更多選項**中找到它。
2. 在確認對話框中按**重載 honk**。
3. 檢查結果提示後，再進行下一項修改。

重載不會套用[暫存規則](routing.md#held-rules)，須另外按其套用按鈕。


## 處理被其他編輯器修改的檔案 {#changed-on-disk}

1. 開啟**組態** → **設定檔**，在**設定檔**中選擇檔案。
2. 若頁面提示磁碟內容已變更，先比較草稿與目前檔案，再決定保留哪個版本。
3. 如需放棄草稿，按**取消**，編輯器會恢復顯示目前來源內容。
4. 如需以草稿覆蓋目前來源，按**保留修改**，再按**套用**。檢查結果，並重新讀取檔案。

**保留修改**不會合併兩個版本。寫入被拒絕時，見[唯讀檔案與寫入錯誤](troubleshooting.md#read-only)。
