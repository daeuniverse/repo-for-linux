# 常见操作 {#common-tasks}

在标准版中调整路由、管理订阅或排查流量。首次配置请从[路由第一条连接](tutorial.md)开始；精简版请参阅 [doona lite](lite.md)。

修改规则前，先检查[规则编辑条件](feature-requirements.md#req-rules)。保存后的生效方式见[配置写入](what-doona-can-change.md#change-sources)。


## 让一个网站通过代理访问 {#one-site}

1. 打开**连接** → **列表**，找到该网站的连接。
2. 点击该行的新增规则图标。
3. 将**依据**设为**完整域名**，将**出站**设为代理组。
4. 检查预览和**插入位置**，把新规则放在可能先匹配同一流量的规则之前。
5. 点击**应用**并检查成功提示。如需集中处理多条修改，先点击**暂存**，再按[暂存规则](routing.md#held-rules)的步骤应用。

如需包含子域名，或让此路由在全局和直连模式下也生效，请按[域名规则步骤](#domain-family)操作。


## 让域名及其子域名通过指定组 {#domain-family}

1. 打开**规则** → **路由规则**。若显示视图切换选项，先选择**高级**，再点击**新建规则**。
2. 将**依据**设为**域名后缀**，在**值**中输入域名。
3. 将**出站**设为目标组。
4. 若全局或直连模式也须遵循此规则，开启**锁定此出站**。
5. 将**插入位置**设在可能先匹配同一流量的规则之前。
6. 点击对话框中的**新建规则**，检查成功提示和列表中的新规则。

其他条件和规则顺序的说明见[规则编辑器](routing.md#add-rule)。


## 让一台设备绕过代理 {#device-bypass}

为设备设置固定 IP 地址，以免地址变化后规则不再匹配。

1. 在**规则** → **路由规则**中，若显示**高级**，先选择它，再点击**新建规则**。
2. 将**依据**设为**来源 IP**，在**值**中输入设备的 IP 地址。
3. 将**出站**设为 `direct`，开启**锁定此出站**。
4. 将**插入位置**设在可能先匹配此设备的规则之前。
5. 点击**新建规则**，检查新规则中的来源地址和出站是否正确。

在[追踪模拟](routing.md#trace)中填入该来源地址，检查最终匹配哪条规则。


## 选择组内节点并恢复自动选择 {#group-node}

先检查[选择节点与手动固定的条件](feature-requirements.md#req-group-selection)。

1. 打开**策略**，展开目标组的卡片。
2. 在节点网格中选择节点。
3. 阅读提示，确认选择结果以及自动策略是否暂停。
4. 如需取消手动固定，打开卡片的**更多操作**菜单，点击**恢复自动选择**，并检查提示中显示的成员。

组策略的说明见[策略组](routing.md#policies)。


## 添加或刷新订阅 {#subscription}

先检查[创建订阅的条件](feature-requirements.md#req-nodes)和单独的[刷新条件](feature-requirements.md#req-subscription-refresh)。

1. 打开**节点**，点击**添加订阅**。
2. 填写**名称**和**订阅网址**，点击**添加**。
3. 选择新订阅卡片，检查节点。后端支持刷新时，doona 会在添加订阅后请求刷新，并提示结果。
4. 以后需要刷新时，点击该卡片的更新按钮。若声明已保存但刷新失败，先解决提示中的错误，再点击更新按钮。

订阅包含节点后，可继续[创建组](tutorial.md)。


## 切换到全局模式 {#global-mode}

先检查[出站模式的修改条件](feature-requirements.md#req-config-edit)。

1. 打开**活动**。
2. 在**出站模式**中选择**全局**，再在**全局出站**中选择目标。
3. 点击**应用**，阅读确认对话框。
4. 在对话框中点击**应用**，检查提示和页面显示的模式。

如需恢复按规则路由，选择**规则**，再点击**应用**。

选择全局出站也会选中全局模式。全局模式未选目标时，**应用**会停用；仅改变选择不会生效。点击**只读**可查看写入限制；**此后端不提供**表示后端没有提供此控件可编辑的配置。


## 查明连接为何使用某个出站 {#why-outbound}

1. 打开**连接** → **列表**，选择目标连接。
2. 在详情中查看**出站**、**链**和**规则**。
3. 在**更多操作**中点击可用的**查看命中的规则**。
4. 如需测试当前配置，点击**追踪此连接**，再点击**开始追踪**。

追踪用于评估路由，不会重播连接。可用条件和结果解读见[追踪条件](feature-requirements.md#req-routing-trace)及[连接详情](observe.md#connections)。


## 查看域名如何解析 {#dns-resolution}

先检查 [DNS 查询条件](feature-requirements.md#req-dns-query)。

1. 打开**DNS** → **查询**。
2. 填写**域名**，选择**类型**。
3. 若提供**上游**，保留**自动**可遵循配置中的 DNS 路由，也可选择指定上游。
4. **略过缓存**默认关闭。若诊断查询需要绕过缓存应答，开启此选项。
5. 点击**查询**，查看结果中的应答、状态、上游和路由信息。

如需查看已记录的流量，打开**解析记录**。数据范围见 [DNS 数据说明](observe.md#dns)。


## 更新地理数据 {#update-geodata}

先检查[手动更新条件](feature-requirements.md#req-geodata-update)。

1. 打开**设置**，找到**地理数据**。
2. 点击**立即更新**。
3. 等待操作完成，检查结果提示和数据文件详情。
4. 若更新失败，按报告的阶段查阅[地理数据更新错误](troubleshooting.md#geodata-update)。

修改来源或更新计划是另一项操作，见[地理数据设置](config-and-settings.md#geodata)及[这些修改的存储位置](what-doona-can-change.md#change-geodata)。


## 在 doona 外修改文件后重载 {#reload-honk}

先确认修改的设置需要[重载还是重启](what-doona-can-change.md)，并检查[后端是否支持重载](feature-requirements.md#req-reload-suspend)。

1. 点击顶栏的**重载 honk**。窄屏下可在**更多选项**中找到它。
2. 在确认对话框中点击**重载 honk**。
3. 检查结果提示后，再进行下一项修改。

重载不会应用[暂存规则](routing.md#held-rules)，须另外点击其应用按钮。


## 处理被其他编辑器修改的文件 {#changed-on-disk}

1. 打开**配置** → **配置文件**，在**配置文件**中选择文件。
2. 若页面提示磁盘内容已变更，先比较草稿和当前文件，再决定保留哪个版本。
3. 如需放弃草稿，点击**取消**，编辑器会恢复显示当前来源内容。
4. 如需以草稿覆盖当前来源，点击**保留修改**，再点击**应用**。检查结果，并重新读取文件。

**保留修改**不会合并两个版本。写入被拒绝时，见[只读文件与写入错误](troubleshooting.md#read-only)。
